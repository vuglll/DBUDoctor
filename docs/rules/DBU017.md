# DBU017: Spot without fallback

Severity: info. Introduced in 0.6.

A classic job or pipeline cluster sets its availability to spot without fallback:
- `aws_attributes.availability: SPOT`;
- `azure_attributes.availability: SPOT_AZURE`;
- `gcp_attributes.availability: PREEMPTIBLE_GCP`.

## Why it matters

Spot capacity can be evicted, or be unavailable when the cluster starts. Without fallback, an eviction can fail the run, and the retry pays for the work again. With the fallback variant, Databricks uses on-demand capacity when spot is not available.

`first_on_demand` places the first nodes, including the driver, on on-demand instances. It defaults to 0 on AWS and to 1 on Azure and GCP ([Clusters API](https://docs.databricks.com/api/workspace/clusters/create), checked 2026-11-09). With 0, the driver runs on spot too, and one eviction ends the run; the message says so.

## Example

```yaml
resources:
  jobs:
    nightly_etl:
      job_clusters:
        - job_cluster_key: main
          new_cluster:
            azure_attributes:
              availability: SPOT_AZURE   # DBU017
```

## How to fix

```yaml
            azure_attributes:
              availability: SPOT_WITH_FALLBACK_AZURE
              first_on_demand: 1
```

## When to suppress

Suppress when the job is cheap to rerun and the lowest price matters more than finishing on time:

```yaml
suppressions:
  - rule: DBU017
    resource: jobs.backfill_*
    reason: Backfills are idempotent and rerun nightly; spot-only is intended
```
