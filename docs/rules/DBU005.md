# DBU005: Continuous job

Severity: warning. Introduced in 0.4.

A job has a `continuous` block whose `pause_status` is not `PAUSED`. An omitted `pause_status` is `UNPAUSED`.

## Why it matters

A continuous job "will ensure that there is always one run executing" ([Jobs API](https://docs.databricks.com/api/workspace/jobs/create), checked 2026-11-09), and a new run starts within 60 seconds of the last one ending ([continuous jobs](https://docs.databricks.com/aws/en/jobs/continuous)). Its compute runs around the clock, about 730 hours a month, whether there is data to process or not.

A job cluster with a driver and 4 workers of `Standard_DS3_v2` on Azure costs about $2.27 an hour (3.75 DBU × $0.30 plus $1.145 of VMs). Run continuously, that is about $1,657 a month. The same job every 15 minutes for 5 minutes runs about 240 hours. DBUDoctor prices an unpaused continuous classic job at its rate × 730 (confidence Medium).

## Example

```yaml
resources:
  jobs:
    events_ingest:
      continuous:
        pause_status: UNPAUSED   # DBU005
      job_clusters:
        - job_cluster_key: main
          new_cluster:
            node_type_id: Standard_DS3_v2
            num_workers: 4
```

## How to fix

Run on a schedule or a trigger that matches how fresh the data must be:

```yaml
resources:
  jobs:
    events_ingest:
      trigger:
        file_arrival:
          url: /Volumes/main/raw/events/
```

For Structured Streaming, a scheduled run with `Trigger.AvailableNow` processes everything new and then stops.

## When to suppress

Suppress when the data must be processed within minutes around the clock and the always-on cost is accepted. Name the latency requirement:

```yaml
suppressions:
  - rule: DBU005
    resource: jobs.events_ingest
    reason: Fraud scoring needs < 2 minute latency (approved in ARCH-57)
```
