# DBU002: All-purpose cluster auto-termination

Severity: warning when auto-termination is disabled, info otherwise. Introduced in 0.4.

A `clusters` resource:
- sets `autotermination_minutes: 0` (a warning);
- or omits the field, or sets it above `rules.DBU002.max_minutes` (default 60) (info).

## Why it matters

An all-purpose cluster bills for every hour it is up, whether anyone runs a command or not. With `autotermination_minutes: 0` it stays up until someone stops it. A cluster with a driver and 4 workers of `Standard_DS3_v2` on Azure costs about $3.21 an hour (3.75 DBU × $0.55 plus $1.145 of VMs), or up to $2,341 a month if it is forgotten. A long idle window costs less but adds up: at 240 minutes, every time people stop working the cluster bills up to 4 more hours, $12.83.

Without the field, the Clusters API does not auto-terminate the cluster ("If not set, this cluster will not be automatically terminated", [Clusters API](https://docs.databricks.com/api/workspace/clusters/create), checked 2026-11-09). The value a bundle deployment ends up with depends on the deployment engine, so DBU002 asks you to state it.

The message uses the cluster's rate from the catalog, with VMs where the catalog has VM prices (Azure).

## Example

```yaml
resources:
  clusters:
    shared:
      spark_version: 15.4.x-scala2.12
      node_type_id: Standard_DS3_v2
      num_workers: 4
      autotermination_minutes: 0   # DBU002 (warning)
```

## How to fix

Set the shortest idle time your users accept. Valid values run from 10 to 10,000 minutes:

```yaml
resources:
  clusters:
    shared:
      autotermination_minutes: 30
```

To allow longer idle windows across the repository, raise the threshold:

```yaml
rules:
  DBU002:
    max_minutes: 120
```

## When to suppress

Suppress when the cluster must stay warm between infrequent requests and its idle cost is approved, for example a cluster behind a BI tool with a strict start-up time. Give the reason and a review date:

```yaml
suppressions:
  - rule: DBU002
    resource: clusters.bi_serving
    reason: BI dashboards need < 10 s start-up; idle cost approved until 2027-03 (FIN-88)
```
