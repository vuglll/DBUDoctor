# DBU011: Scheduled serverless job in performance-optimized mode

Severity: info. Introduced in 0.7.

A job with serverless tasks runs on a schedule or a periodic trigger, and its `performance_target` is absent or `PERFORMANCE_OPTIMIZED`. The API default is `PERFORMANCE_OPTIMIZED`.

## Why it matters

"Both modes use the same SKU, but standard performance mode consumes fewer DBUs, reflecting lower compute usage." Standard mode suits "workloads that can tolerate slightly higher startup latency of 4 to 6 minutes" ([serverless jobs](https://docs.databricks.com/aws/en/jobs/run-serverless-jobs), checked 2026-11-09). A nightly or hourly batch job rarely needs to start within seconds, so it pays for speed it does not use. The default is `PERFORMANCE_OPTIMIZED` ([Jobs API](https://docs.databricks.com/api/workspace/jobs/create)).

With [calibration](../calibration.md), DBUDoctor estimates the switch from the job's observed DBUs × `estimation.standard_mode_factor` (0.7 by default).

## Example

```yaml
resources:
  jobs:
    nightly_report:          # DBU011: no performance_target, so performance-optimized
      schedule:
        quartz_cron_expression: "0 0 2 * * ?"
        timezone_id: UTC
      tasks:
        - task_key: report
          environment_key: default
          notebook_task:
            notebook_path: ../src/report.py
```

## How to fix

```yaml
resources:
  jobs:
    nightly_report:
      performance_target: STANDARD
```

## When to suppress

Suppress when the job must start within seconds of its schedule:

```yaml
suppressions:
  - rule: DBU011
    resource: jobs.market_open_prices
    reason: Prices must publish within 1 minute of market open (TRD-5)
```
