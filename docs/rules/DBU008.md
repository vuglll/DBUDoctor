# DBU008: Missing cost-attribution tags

Severity: warning. Introduced in 0.5. Off until you set `rules.DBU008.required_tags`.

A job, pipeline, cluster or SQL warehouse lacks a tag key your organization requires, in the places where tags reach billing:

| Resource | Tag locations |
|---|---|
| Job | `tags`, and `custom_tags` on its job clusters or task clusters |
| Pipeline | `tags`, and `custom_tags` on its clusters |
| Cluster | `custom_tags` |
| SQL warehouse | `tags.custom_tags` |

A serverless job or pipeline with a `usage_policy_id` (or the older `budget_policy_id`) counts as attributed: usage policies tag serverless usage.

## Why it matters

Cost reports, in the cloud bill and in `system.billing.usage`, group spend by tags. A resource without the attribution tags lands in "unallocated", so nobody sees or owns its cost. Tag keys are compared exactly, as billing groups them: `Team` does not satisfy `team`.

## Example

```yaml
# .dbudoctor.yml
rules:
  DBU008:
    required_tags: [team, cost_center]
```

```yaml
resources:
  jobs:
    nightly_etl:
      tags:
        team: data-platform   # DBU008: cost_center is missing
```

## How to fix

Add the missing keys with the owner's values:

```yaml
resources:
  jobs:
    nightly_etl:
      tags:
        team: data-platform
        cost_center: "4711"
```

For serverless jobs and pipelines, attach a usage policy that sets the tags (`usage_policy_id`).

## When to suppress

Suppress for shared infrastructure whose cost is split by another mechanism, and say which:

```yaml
suppressions:
  - rule: DBU008
    resource: sql_warehouses.shared_bi
    reason: Shared BI warehouse; cost split by query tags in FinOps report (FIN-12)
```
