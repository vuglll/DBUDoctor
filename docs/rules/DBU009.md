# DBU009: Large on-demand cluster

Severity: info. Introduced in 0.6.

A classic job or pipeline cluster meets both conditions:
- it has at least `rules.DBU009.min_workers` workers (default 8; the maximum, for autoscale);
- it sets its availability explicitly to on-demand: `ON_DEMAND` (AWS), `ON_DEMAND_AZURE` or `ON_DEMAND_GCP`.

## Why it matters

Batch workers tolerate spot capacity well, and spot VMs cost a fraction of on-demand. With spot with fallback, a worker that cannot get spot capacity starts on demand instead. `first_on_demand` keeps the driver, and any other first nodes, on demand ([Clusters API](https://docs.databricks.com/api/workspace/clusters/create), checked 2026-11-09).

Where the catalog has spot prices (Azure), the message gives the saving. For example, 16 `Standard_DS3_v2` workers at $0.229 on demand against $0.05 spot save up to $2.86 an hour on VMs. Eviction and fallback are not modeled.

A cluster that does not set availability is not reported. The API defaults are spot with fallback on AWS and on-demand on Azure and GCP.

## Example

```yaml
resources:
  jobs:
    nightly_etl:
      job_clusters:
        - job_cluster_key: main
          new_cluster:
            node_type_id: Standard_DS3_v2
            autoscale: { min_workers: 2, max_workers: 16 }
            azure_attributes:
              availability: ON_DEMAND_AZURE   # DBU009
```

## How to fix

```yaml
            azure_attributes:
              availability: SPOT_WITH_FALLBACK_AZURE
              first_on_demand: 1
```

## When to suppress

Suppress when the workload cannot tolerate losing workers mid-run, for example a long stateful job without checkpoints:

```yaml
suppressions:
  - rule: DBU009
    resource: jobs.month_end_close
    reason: 6 h close job without checkpoints; eviction restarts cost more (FIN-33)
```
