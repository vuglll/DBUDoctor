# DBU004: Continuous pipeline

Severity: warning. Introduced in 0.1.

A pipeline sets `continuous: true`.

## Why it matters

A continuous pipeline keeps its compute running around the clock, about 730 hours a month, instead of only while an update runs. A triggered pipeline that runs every 15 minutes for 5 minutes uses about a third of that. DBUDoctor prices a continuous classic pipeline at its hourly rate × 730 (confidence Medium).

## Example

```yaml
resources:
  pipelines:
    events:
      continuous: true   # DBU004
      edition: CORE
      clusters:
        - label: default
          node_type_id: Standard_DS3_v2
          autoscale: { min_workers: 1, max_workers: 2 }
```

## How to fix

Run the pipeline in triggered mode and start it from a job on a schedule that matches how fresh the data must be:

```yaml
resources:
  pipelines:
    events:
      continuous: false
  jobs:
    events_refresh:
      schedule:
        quartz_cron_expression: "0 0/15 * * * ?"
        timezone_id: UTC
      tasks:
        - task_key: refresh
          pipeline_task:
            pipeline_id: ${resources.pipelines.events.id}
```

For latency needs between those two, consider a shorter schedule or serverless before running continuously.

## When to suppress

Suppress when the data must stay fresh within minutes and the always-on cost is accepted. Name the latency requirement:

```yaml
suppressions:
  - rule: DBU004
    resource: pipelines.events
    reason: Fraud alerts need < 1 minute latency (approved in ARCH-42)
```
