# DBU012: Outdated or end-of-support runtime

Severity: warning past end of support, info within `rules.DBU012.warn_days` (default 90) of it. Introduced in 0.5.

A job cluster, task cluster or all-purpose cluster sets a `spark_version` whose LTS release:
- is past its end-of-support date in [catalog/runtimes.yaml](../../catalog/runtimes.yaml) (a warning);
- reaches that date within `warn_days` (info).

Runtimes older than every listed release are past end of support too.

## Why it matters

After end of support a runtime gets no security fixes, and older runtimes miss the engine improvements that make the same work run faster and cheaper. LTS releases are supported for three years after release ([support lifecycles](https://docs.databricks.com/aws/en/release-notes/runtime/databricks-runtime-ver), checked 2026-11-09). For example, 13.3 LTS reached end of support on 2026-08-22, and 14.3 LTS reaches it on 2027-02-01 ([runtime release notes](https://docs.databricks.com/aws/en/release-notes/runtime/)). "Databricks Runtime 10.4 LTS and earlier have reached end-of-life" ([end-of-support releases](https://docs.databricks.com/aws/en/release-notes/runtime/eos)).

The catalog lists LTS releases only. Non-LTS releases end six months after release and are not checked, and neither are runtimes 18 and later until their `spark_version` format is documented. Dates are compared with today's date (UTC).

## Example

```yaml
resources:
  jobs:
    nightly_etl:
      job_clusters:
        - job_cluster_key: main
          new_cluster:
            spark_version: 13.3.x-scala2.12   # DBU012: end of support 2026-08-22
```

## How to fix

Move to a current LTS release after testing the job on it:

```yaml
            spark_version: 16.4.x-scala2.12
```

## When to suppress

Suppress when the workload depends on a library that does not run on newer runtimes and a migration is planned:

```yaml
suppressions:
  - rule: DBU012
    resource: jobs.legacy_scoring
    reason: Needs a library pinned to Spark 3.4; migration planned for 2027-01 (DATA-77)
```
