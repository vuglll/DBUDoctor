# DBU018: Pipeline cluster on legacy autoscaling

Severity: info. Introduced in 0.6.

A classic pipeline cluster sets `autoscale.mode: LEGACY`. Maintenance clusters, which always use legacy autoscaling, and serverless pipelines are skipped.

## Why it matters

Enhanced autoscaling sizes the cluster to the pipeline's workload: it adds workers when the queue grows and removes them when it shrinks. "Enhanced autoscaling is enabled by default for all new pipelines" ([enhanced autoscaling](https://docs.databricks.com/aws/en/ldp/auto-scaling), checked 2026-11-09). `LEGACY` uses plain cluster autoscaling, which keeps workers around longer than the work needs. A pipeline that still sets it usually does so out of habit, and pays for the idle workers.

## Example

```yaml
resources:
  pipelines:
    events:
      clusters:
        - label: default
          autoscale:
            min_workers: 1
            max_workers: 8
            mode: LEGACY   # DBU018
```

## How to fix

```yaml
          autoscale:
            min_workers: 1
            max_workers: 8
            mode: ENHANCED
```

Or remove `mode` to take the default.

## When to suppress

Suppress when you have measured the pipeline to run cheaper with legacy autoscaling:

```yaml
suppressions:
  - rule: DBU018
    resource: pipelines.events
    reason: Measured 12% cheaper on LEGACY for this steady stream (PERF-8)
```
