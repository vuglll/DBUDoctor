# DBU003: SQL warehouse auto-stop

Severity: warning when auto-stop is disabled, info otherwise. Introduced in 0.4.

A SQL warehouse:
- sets `auto_stop_mins: 0` (a warning);
- or its effective auto-stop is longer than `rules.DBU003.max_minutes` (default 30) (info).

When the field is absent, the effective value is the platform default in [catalog/defaults.yaml](../../catalog/defaults.yaml).

## Why it matters

"Idle SQL warehouses continue to accumulate DBU and cloud instance charges until they are stopped" ([Databricks docs](https://docs.databricks.com/aws/en/compute/sql-warehouse/create), checked 2026-11-09).
- **Never stops:** a serverless `Small` warehouse on Azure costs $8.40 an hour (12 DBU × $0.70), so one that never stops can bill up to $6,132 a month.
- **Unset:** the SQL Warehouses API default is 120 minutes ([API reference](https://docs.databricks.com/api/workspace/warehouses/create)). Every time the last dashboard closes, the warehouse bills up to two more hours, $16.80. The UI defaults are shorter (45 minutes for pro and classic, 10 for serverless), but bundles deploy through the API.

The message uses the warehouse's rate from the catalog, with VMs for classic and pro warehouses where the catalog has VM prices (Azure).

## Example

```yaml
resources:
  sql_warehouses:
    bi:
      cluster_size: Small
      enable_serverless_compute: true
      # auto_stop_mins not set: the API default of 120 minutes applies (DBU003, info)
```

## How to fix

Set the shortest idle time your users accept. The API accepts 0 or at least 10 minutes, and serverless warehouses from 1 minute:

```yaml
resources:
  sql_warehouses:
    bi:
      auto_stop_mins: 10
```

To allow longer idle times across the repository, raise the threshold:

```yaml
rules:
  DBU003:
    max_minutes: 45
```

## When to suppress

Suppress when dashboards or users need the warehouse warm between infrequent queries and the idle cost is approved. Give the reason and a review date:

```yaml
suppressions:
  - rule: DBU003
    resource: sql_warehouses.exec_dashboards
    reason: Board dashboards must load instantly during business hours; approved until 2027-03 (FIN-91)
```
