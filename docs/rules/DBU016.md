# DBU016: Classic job cluster on a short schedule

Severity: info. Introduced in 0.4.

A job meets both conditions:
- it runs on a classic job cluster without `instance_pool_id`;
- its schedule or periodic trigger fires more often than every `rules.DBU016.min_interval_minutes` (default 15), measured as the shortest interval between runs.

## Why it matters

A job cluster is created for each run and released when the run ends. A job every 5 minutes starts a cluster about 8,760 times a month (12 runs an hour × 730 hours), and each run waits for, and pays for, the cluster start-up before any work begins.

Pools keep idle instances ready: "When cluster nodes are created using the idle instances, cluster start and auto-scaling times are reduced" ([instance pools](https://docs.databricks.com/aws/en/compute/pool-index), checked 2026-11-09). The same page says Databricks recommends serverless compute over pools when the workload supports it.

DBUDoctor counts the cluster starts but does not price them: no Databricks source gives a start-up time for classic job clusters.

## Example

```yaml
resources:
  jobs:
    orders_sync:
      schedule:
        quartz_cron_expression: "0 0/5 * * * ?"   # DBU016
        timezone_id: UTC
      job_clusters:
        - job_cluster_key: main
          new_cluster:
            node_type_id: Standard_DS3_v2
            num_workers: 2
```

## How to fix

Run the tasks on serverless compute, for example by removing the job cluster and giving Python tasks an `environment_key`. Or start the job cluster from an instance pool:

```yaml
      job_clusters:
        - job_cluster_key: main
          new_cluster:
            instance_pool_id: ${var.pool_id}
            num_workers: 2
```

If the job really needs to run all the time, a `continuous` job keeps one run going without a cluster start every few minutes (see [DBU005](DBU005.md) for its cost).

## When to suppress

Suppress when the workload needs classic compute that pools cannot provide, and the start-up overhead is accepted:

```yaml
suppressions:
  - rule: DBU016
    resource: jobs.orders_sync
    reason: Needs GPU nodes not offered in our pools; start-up accepted (PLAT-12)
```
