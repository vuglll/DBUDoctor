# DBU015: Lakebase endpoint sizing

Severity: warning for an always-active compute off production, info for a large minimum. Introduced in 0.8.

A Lakebase Autoscaling compute (`postgres_endpoints`) meets either condition:
- it disables scale to zero (`no_suspension: true`) on a branch that is not a production branch (a warning);
- it keeps `autoscaling_limit_min_cu` at `rules.DBU015.max_min_cu` (default 8) or more (info).

Production branches are `production`, the root branch of every project, and any branch in `rules.DBU015.production_branches`. The branch comes from the compute's `parent`, `projects/<project>/branches/<branch>`.

## Why it matters

"You pay only for active compute time, not for idle periods", and a suspended compute "incurs no compute costs" ([scale to zero](https://docs.databricks.com/aws/en/oltp/projects/scale-to-zero), checked 2026-11-10). Development and preview branches sit idle most of the day. Keeping them always active bills every hour: 2 CU on Azure at $0.30 per DBU and 0.213 DBU per CU is about $93 a month per compute. The message gives the figure from DBUDoctor's Lakebase pricing.

A high minimum is billed for every active hour, and autoscaling adds capacity when the database is busy. Computes autoscale between 0.5 and 64 CU, with at most 16 CU between minimum and maximum ([manage computes](https://docs.databricks.com/aws/en/oltp/projects/manage-computes)).

## Example

```yaml
resources:
  postgres_endpoints:
    dev_primary:
      parent: projects/shop/branches/dev
      autoscaling_limit_min_cu: 2
      autoscaling_limit_max_cu: 4
      no_suspension: true   # DBU015 (warning)
```

## How to fix

Let the compute scale to zero, with a timeout if the default is too short:

```yaml
    dev_primary:
      suspend_timeout_duration: 300s
```

And size the minimum to the idle load.

## When to suppress

Suppress when the branch serves traffic that cannot wait for a cold start, or the minimum matches a measured baseline:

```yaml
suppressions:
  - rule: DBU015
    resource: postgres_endpoints.staging_primary
    reason: Staging runs the 24/7 synthetic checkout monitor (OPS-40)
```
