# DBU001: Task runs on all-purpose compute

Severity: warning. Introduced in 0.1.

A job task sets `existing_cluster_id`, so it runs on an all-purpose cluster. All-purpose compute is billed at the all-purpose DBU rate, which is much higher than the Jobs compute rate.

## Why it matters

Databricks bills the same work at different rates depending on where it runs. The message shows the Jobs compute DBU rate as a percentage of the all-purpose rate, from the catalog for the bundle's cloud and region. For example, Azure lists Jobs compute at $0.30 per DBU and all-purpose at $0.55, so a job cluster costs about 55% of the all-purpose rate per DBU. On AWS (seed prices $0.15 and $0.55) it is about 27%.

A shared all-purpose cluster also tends to stay up between runs, and its size is set for interactive users, not for the job.

## Example

```yaml
resources:
  jobs:
    report_refresh:
      tasks:
        - task_key: refresh
          existing_cluster_id: 0601-182128-dcbte59m   # DBU001
          notebook_task:
            notebook_path: ../src/refresh.ipynb
```

## How to fix

Give the task a job cluster:

```yaml
resources:
  jobs:
    report_refresh:
      job_clusters:
        - job_cluster_key: main
          new_cluster:
            spark_version: 15.4.x-scala2.12
            node_type_id: Standard_DS3_v2
            num_workers: 2
      tasks:
        - task_key: refresh
          job_cluster_key: main
          notebook_task:
            notebook_path: ../src/refresh.ipynb
```

Or use `new_cluster` on the task, or remove the cluster settings to run on serverless compute (`environment_key` for Python tasks).

## When to suppress

Suppress when the task needs state that lives on the shared cluster (cached tables, libraries installed by hand), or when it runs so rarely that a job cluster's startup costs more than the price difference. Say why and when that will change:

```yaml
# .dbudoctor.yml
suppressions:
  - rule: DBU001
    resource: jobs.report_refresh
    reason: Uses the shared cluster's cached lookup tables until the Q1 migration (JIRA-123)
```
